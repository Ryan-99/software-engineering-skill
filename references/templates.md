# 门禁文档模板

零占位符原则同样适用于这些文档：【】字段写不出来就先问用户，不留空交付。模板按需裁剪小节，删掉无内容的小节而非留"暂无"。

**注意**：小节名（如"成功标准""验收核验"）是 `scripts/check_gate.mjs` 的机械检查目标，改名须同步脚本并跑 selftest。需求条目必须用 `### FR-n` 块格式（含 描述/优先级/AC-x.y），校验器按此解析；不要改回表格。

## pipeline.json（状态机，两档通用）

````json
{
  "project": "<项目名>",
  "tier": "light",
  "gates": [
    { "id": "GB", "status": "confirmed", "confirmed_at": "2026-10-12" },
    { "id": "GD", "status": "in-review" },
    { "id": "G4", "status": "pending" },
    { "id": "G5", "status": "pending" }
  ],
  "changes": [
    { "date": "2026-10-13", "gate": "GB", "summary": "新增导出功能 FR-3，Ryan 确认" }
  ],
  "bypass": []
}
````

- 轻量档 gates 固定为 `["GB","GD","G4","G5"]`；完整档固定为 `["G0","G1","G2","G3","EXEC","G4","G5"]`（EXEC 无文档，标记执行期开始/结束）。
- status 取值：pending / draft / in-review / confirmed / bypassed；confirmed 必带 `confirmed_at`(YYYY-MM-DD)，bypassed 必带 `"reason": "<用户原话或理由>"`（直接写在 gate 对象上）。
- 确认发生的那一刻立即写入此文件；聊天记忆不算确认记录。

## BRIEF.md（轻量档：GB=立项+需求）

````markdown
# 项目简报：<项目名>

## 背景与目标
<一句话说清做什么、为谁解决什么问题>

## 范围
- 做：<功能点列表>
- 不做（非目标）：<明确排除项>

## 成功标准
<可验证的判定句，如"导入 100 条数据无丢失且 <3s">

## 需求清单
### FR-1 <功能名>
- 描述：<做什么>
- 优先级：必须/应该/可以
- 验收标准：AC-1.1 <可测判定句>

## 非功能需求
<性能/安全/兼容/部署环境，没有则写"无特殊要求"并说明理由>

## 约束与风险
- 约束：<时间/技术栈/平台>
- 风险：<风险 → 应对>
````

## PLAN.md（完整档 G3）

````markdown
# 项目计划：<项目名>

**目标**：<一句话>
**技术架构摘要**：<两三句>
**规格链接**：docs/REQUIREMENTS.md（计划从规格论证，规格随计划走，执行者两份都读）

## 全局约束
<从规格逐字拷贝的硬约束：版本底线/命名/红线，一行一条；每个任务隐含继承>

## 任务分解（概览）
| 编号 | 任务 | 依赖 | 状态 |
|---|---|---|---|

## 任务卡
### T-1 <任务名>
- 目标：<做什么，边界（不做什么）>
- 涉及文件：Create/Modify <精确路径>
- Interfaces：
  - Consumes：<用上游任务的哪些签名，贴原文>
  - Produces：<下游任务依赖我的哪些签名，精确到参数与返回类型>
- 步骤：
  - [ ] <一步一个动作：写失败测试/看它失败/最小实现/跑过/commit>
- 验证：<可执行命令>
  - 期望：<期望输出/失败数>

（任务卡粒度=最小独立可评审单元；Interfaces 的签名要让零记忆实现代理能对齐邻居任务的命名）

## 评审盲区
<规格暗示但没有任何测试覆盖、最可能咬人的输入类别，一行一条；每条在所属任务补测试>

## 里程碑
| 节点 | 内容 | 对应门禁 |
|---|---|---|

## 测试策略
<金字塔分层 + AC→测试映射表>

## 风险与应对
````

提交确认前做计划自检：①规格覆盖（每条 FR/AC 指得到任务）②占位符扫描（TBD/"类似任务N"违禁）③跨任务命名一致 ④评审盲区逐条有测试。

## 质量门禁
| 项 | 结果 |
|---|---|
| typecheck | |
| lint | |
| 单元/集成测试 | |
| E2E | |

## 缺陷表
| 编号 | 复现步骤 | 严重度 | 状态 |
|---|---|---|---|

<是否达到验收条件，遗留项>
